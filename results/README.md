# 复现结果汇总（results）

> **位置说明**：本目录位于代码仓库内部（`av_hubert_train/results/`），
> 后续所有结果都在这里更新——这样结果与产生它的代码、配置、日志在同一棵目录树里，
> 用 git 一起管理，不会出现"代码改了、结果对不上"的情况。
> 原始产物由 `scripts/remote/collect_results.py`（**就在本仓库内**）
> 从实例上归集到 `04_原始产物/`。
>
> `results/` 未被 `.gitignore` 排除（已用 `git check-ignore` 核实），
> 可以随代码一起提交；其中最大的文件是 545 KB 的全流程日志。

本目录汇总任务三「在 LRS2 上复现 AV-HuBERT 并给出纯视觉测试结果」的**全部实测结果**。
每条数字都注明来源与复现方式。

## 结论速览

| 项目 | 结果 |
| --- | --- |
| 数据集 | LRS2 **main**（train 45,839 / val 1,082 / test 1,243 条） |
| 数据流水线 | 7 步全部完成并通过验收：audio / landmark / video 各 **48,164**，`data/` 9 个文件（纯视觉模式下第 2 步抽音频整步跳过，本次 audio 是改动前留下的产物） |
| 预训练权重 | 官方 `base_vox_iter4.pt`（LRS3+VoxCeleb2 自监督预训练，**base**：编码器 12 层 × 768 维、sha256 已核对） |
| 微调 | 单卡 RTX 3090，纯视觉（`task.modalities: ["video"]`），8,000 步，实测 **44.3 分钟** |
| **LRS2 test 全量（1,243 条）WER** | **52.97%**（err 3,528 / 参考词 6,660） |
| **LRS2 test MV 子集（246 条）WER** | **56.96%**（err 708 / 参考词 1,243） |
| 解码 | seq2seq beam search，**beam = 10**，未用语言模型 |
| WER 口径 | **按空格切词、保留撇号与标点**（fairseq 默认）；换成"切分标点"的口径则为 53.80% / 59.12%，比较时须确认口径 |

> 这两条就是题目要汇报的「点数」。逐句层面：**0 条空输出**、
> **14.6% 的句子完全正确**、逐句中位 WER 50%——模型确实在做唇读，
> 错误多为合理的唇形混淆（`say→stay`、`taxation→asssions`）。
>
> ⚠️ 一个需要写明的反常观测：通常认为 `MV`（mouth-visible）子集应更简单，
> 但实测 **MV 的 WER 反而更高**（56.96% > 52.97%）。
> 已核实**不是取错子集**（本地 `test.txt` 的 MV 标签集合与远端 `test_mv.tsv`
> 完全一致，双向差集均为 0，246 条），也**不是句长构成不同造成的**
> （短句占比 21.1% vs 19.4%，且在 4–6 / 7–10 词两个桶内 MV 都更差）。
> 但 n=246 时该差异**未达常规显著性**（长度分层置换检验 p ≈ 0.074，单侧），
> 因此只作为**现象记录**，不作结论。详见 `02_微调与解码/配置与结果.md` §1.2。
> 另外需说明：两份官方要求文件都没有提到过 `MV`/`NF` 标签。
>
> ⚠️ 本次为在单卡有限时间内出结果，采用了**省时配置**（8,000 步、
> 编码器全程冻结、beam 10）。这三点都是已知的精度取舍，
> 官方 base 配方是 45,000 步 + 后 22,500 步解冻编码器。
> 因此 52.97% 应理解为"算力受限下的结果"，不是该方法上限；
> 另外验证曲线显示**收益已在明显递减**（每 2000 步的准确率增量 14.55 → 4.62 → 1.70），
> 所以提升重点是**解冻编码器 / 加语言模型**，而不是单纯加步数。
> 提升路径与命令见 `02_微调与解码/配置与结果.md` §6。
