## 1. 主结果

| 评测口径 | 样本数 | beam | **WER** | err / 参考词数 |
| --- | --- | --- | --- | --- |
| **LRS2 `test`（全量，主口径）** | 1,243（其中 MV 246 / NF 997） | 10 | **52.97%** | 3,528 / 6,660 |
| **LRS2 `test_mv`（仅 mouth-visible 子集）** | 246 | 10 | **56.96%** | 708 / 1,243 |

> **WER 口径**：**按空格切词、保留撇号与标点**（`it's` 算一个词），即 fairseq 默认口径。
> 换成"先切分标点"的口径，同一批假设给出 **53.80%（test）/ 59.12%（MV）**。
> 与论文数字比较前请确认口径一致。

逐句层面：**0 条空输出**、test 上 **14.6% 的句子完全正确**、逐句中位 WER 50%。
典型错误是合理的唇形混淆（`say→stay`、`taxation→asssions`、`consent of parliament→extensions of parment`），
说明模型确实在做唇读而不是输出垃圾。

> 反常观测（如实记录）：`MV`（mouth-visible）子集实测 **WER 反而更高**
> （56.96% > 52.97%）。已核实**不是取错子集**（本地 `lrs2_datalist/test.txt` 的标签分布为
> NF 997 / MV 246，远端 `data/test_mv.tsv` 恰好 246 条且 fid 集合与其完全一致，
> 双向差集均为 0），也**不是句长构成不同**造成的（短句占比 21.1% vs 19.4%，
> 且 4–6 / 7–10 词两个桶内 MV 都更差）。
> **但 n=246 时该差异未达常规显著性**（长度分层置换检验 p ≈ 0.074，单侧），
> 故只作现象记录、不作结论。另需说明：两份官方要求文件都**没有**提到过 `MV`/`NF` 标签，
> 所以这里不存在"与题目材料相矛盾"，只是与直觉相反。

> 口径说明：本结果用的是**省时配置**（8,000 步、编码器全程冻结、beam 10），
> 官方 base 配方是 45,000 步 + 后一半解冻编码器。因此该点数应理解为
> "算力受限下的结果"。且验证曲线显示**收益已在明显递减**
> （每 2000 步准确率增量 14.55 → 4.62 → 1.70），提升重点应是
> **解冻编码器 / 加语言模型**而非单纯加步数；
> 详见 `../results/02_微调与解码/配置与结果.md` §6。

## 3. 与论文的对比说明

- 论文（*Learning Audio-Visual Speech Representation by Masked Multimodal Cluster
  Prediction*）的主结果是 **LRS3** 上的，本项目按要求在 **LRS2** 上评测，
  **两者数据集不同，数字不能直接比大小**，对比时要说清：
  - 预训练语料：官方权重来自 LRS3(+VoxCeleb2)，LRS2 只是微调目标域；
  - 数据规模：LRS2 main train 45,839 条（约 29 小时），远小于 LRS3 的 433 小时；
  - 评测集：LRS3 test / LRS2 test 的说话人与录制条件都不同。
- 可比的部分是**配置口径**：官方 base 模型 LRS3 上的 video-only 结果由
  `finetune/base_vox_433h.yaml` 这一类配置得到（`is_s2s: true` + beam search），
  本项目沿用同一路线，只把数据换成 LRS2。

### 3.1 需要主动披露的两处口径细节

1. **词表是在「全部标签」上训练的，含 test 的转写**：`lrs2_manifest.py` 沿用官方
   `lrs3_manifest.py` 的做法（把 `label.list` 全量喂给 sentencepiece）。
   这会让目标端词表"见过"测试集文本，属于**官方原有行为**，本项目保持一致；
   汇报时应写明，避免被理解成我们额外做了调优。
   （另：`dict.wrd.txt` 实测 996 行，说明 `vocab_size=1000` 正常生效、没有触发降级。）
2. **数据划分已核实无泄漏**：train/val/test 三个列表实测 **0 重复 fid、
   两两交集为空、无共享 video_id**；45,839 + 1,082 + 1,243 = 48,164 与 `main/` 内容一致。

## 4. 需要向评审说明的一处口径差异

任务要求 §3.3.5 写的是「**CTC 贪心解码**」，但：
- 官方仓库的 LRS2/LRS3 微调配置全部是 **seq2seq**（Transformer 解码器 + beam search），
  论文里视频唇读的主要结果也是 seq2seq；
- 同一份要求的 §3.3.6 又要求写明「**是否 beam search**」，说明 beam search 是被接受的；
- 因此本项目**跟随仓库自带配置用 seq2seq + beam search**，并在结果表里写明 beam 值。
  若评审坚持要 CTC 口径（贪心解码），需要另配 `criterion: ctc` 的微调实验，
  本仓库未做（官方也没有现成的 LRS2 CTC 配置）。

## 5. 复跑命令（一键 + 分步）

```bash
# 一键（流水线 -> 帧缓存 -> 微调 -> 解码 test/test_mv 并打印 WER）
# 注意：脚本会自己 source 环境文件（可用 AVH_ENV 指定）、并接受 WORK/EXP/LRS2_ROOT/
# DATALIST/DLIB/FFMPEG 等环境变量覆盖，不依赖仓库放在某个固定路径。
export LRS2_ROOT=/hy-tmp/main DATALIST=/hy-tmp/lrs2_datalist WORK=/hy-tmp/lrs2_data
export FFMPEG=$(which ffmpeg) DLIB=/hy-tmp/dlib NSHARD=8 MODALITY=video
bash scripts/run_reproduce.sh full

# 只冒烟验证链路（30 条数据 + 20 步训练 + 解码，约 5 分钟）
bash scripts/run_reproduce.sh smoke

# 分步
bash scripts/pipeline_lrs2.sh all                     # 1) 预处理（7 步，含完整性验收）
python scripts/build_frame_cache.py --work-dir "$WORK" --out "$WORK/frame_cache" --workers 8 --verify 30
export DATA=$WORK/data CKPT=$PWD/pretrained/base_vox_iter4.pt EXP=/hy-tmp/exp
bash scripts/run_finetune.sh fast                     # 2) 微调
BEAM=10 bash scripts/run_finetune.sh test "$EXP/fast/checkpoints/checkpoint_best.pt" test      # 3) 解码
BEAM=10 bash scripts/run_finetune.sh test "$EXP/fast/checkpoints/checkpoint_best.pt" test_mv
```

> ⚠️ 关于帧缓存：**交付的那次训练并没有用上帧缓存**——构建时索引发布失败
> （`np.savez` 对不以 `.npz` 结尾的文件名会自动加后缀），训练回退到在线解码完成，
> 实际生效配置里 `video_cache: None`（见 `../results/02_微调与解码/配置与结果.md` §3.1）。
> 因此若想**逐位复现**交付结果，请按上面这样**不带 `EXTRA=task.video_cache=...`** 跑；
> 带上缓存会得到等价但更快的结果（缓存帧与在线解码已校验逐位一致）。
> 早先这里给的命令带了 `task.video_cache=$WORK/frame_cache`，与交付实跑不符，已更正。
