# 对官方仓库的修改记录

> 任务要求 §3.4 要求交付「可运行的代码/脚本，以及对官方仓库所做的**修改记录**
> （改了哪些文件、为什么改）」。本文即该记录。
>
> 官方仓库：<https://github.com/facebookresearch/av_hubert>
> 本记录基于 `git status` / `git diff` 实测得出（对比本仓库提交 `eb86e23`），
> 不是回忆性描述。

---

## 0. 总体思路

官方代码只在 **LRS3** 上训练/测试，数据准备脚本也是为 LRS3 写的。本项目的改动
遵循三条原则：

1. **算法与模型结构一律不动**：`fairseq/`、`avhubert/hubert.py`、`resnet.py`、
   `sequence_generator.py` 等核心实现保持原样，只做 LRS2 的数据适配。
2. **预处理脚本按题目允许重写**：`Dataset.md` 明确写了「请根据任务实际情况考虑
   是否使用我们提供的数据预处理，或进行相应修改」，并且「数据集缺少 pretrain 部分，
   部分代码需要相应调整」。
3. **每处改动都写明"为什么"**，尤其是踩过的坑（这些坑写在代码注释里，换个人
   复跑时能省时间）。

## 2. 修改的官方文件

### 2.1 数据准备相关（`avhubert/preparation/`）

| 文件 | 改了什么 | 为什么 |
| --- | --- | --- |
| `count_frames.py` | ① 新增 `--video-only`：不读 wav，音频帧数列写 0 占位；② 数帧前检查 `cap.isOpened()` 与帧数为正 | ① 纯视觉训练**从不读音频**（见 `代码审查与优化记录.md` §1.1），原来的实现白读 4.8 万个 wav；② 原实现打不开的 mp4 会返回 0 并被当成有效样本写进 manifest，最后炸在训练时 |
| `detect_landmark.py` | ① 支持**断点续跑**（产物存在且能被 `pickle.load` 就跳过）；② 改为「先写临时文件再 `os.replace`」原子落盘 | 原实现没有任何跳过逻辑，任何中断都会让最慢的一步（8 rank 下仍要数小时）从头再来；原子写保证"存在即完整"，让跳过是安全的 |
| `align_mouth.py` | ① 重采样从 `skimage.transform.warp` 换成 `cv2.warpAffine`（**4.4×**）；② 写视频从「逐帧 PNG + concat 回读」换成 rawvideo 管道（**逐位一致**，省掉约 240 万个临时 PNG）；③ 检查 ffmpeg 返回码；④ 失败时删掉半截产物；⑤ 修 `trans` 未赋值就使用的隐患 | ①② 唇部 ROI 是最慢的一步之一（全量约数小时），这两处是实测出来的瓶颈；③④ 原实现丢掉返回码，失败只表现为"文件不存在"，而且残缺文件会被"存在就跳过"永久信任；⑤ 官方原实现在帧数 < window_margin 时会抛 `UnboundLocalError` |
| `lrs2_manifest.py` | ① sentencepiece 在语料过小时按报错上限**自动降级**重试（小样本验证必要）；② 记录 `vocab_size.txt`，并在"已有词表是降级产物、本次要全量"时**删除重训** | ① `LIMIT=30` 时 `vocab_size=1000` 必然失败；② 原来降级产物仍以 `spm_unigram1000.*` 命名且记录无人读，全量运行时会把几十个 piece 的降级词表静默拿去用 |

### 2.2 训练/评测相关

| 文件 | 改了什么 | 为什么 |
| --- | --- | --- |
| `hubert_dataset.py` | `load_video` 支持可选的**预解码帧缓存**（未命中自动回退在线解码） | 实测数据加载是训练瓶颈（每 clip 约 16 ms 解码） |
| `hubert_pretraining.py` | 新增 `task.video_cache` 配置项（默认 `null`，不设时行为与原来完全一致） | 同上 |
| `utils.py` | ① 新增 `FrameCache`（内存映射读预解码帧，按 pid 惰性打开，缺失/不配套时安全退化）；② `Normalize` 显式转 float32 | ① 见上；② 原来 uint8 与 python float 相减被提升成 **float64**，而出口本来就要 `astype(np.float32)`，白白多搬一倍数据 |
| `conf/finetune/*.yaml` | ① `# @package _group_` → `# @package _global_`；② **解码器尺寸从 large 的 1024/4096/9/8 改回 base 默认的 768/3072/6/4**，并把调度改回官方 base（`max_update 45000` / `warmup 15000` / `decay 30000` / `freeze_finetune_updates 22500` = 一半） | ① Hydra ≥1.1 里 `_group_` 指"配置所在分组目录"，本文件在 `conf/finetune/` 下，会把所有键挂到 `finetune.*`，导致 `common.user_dir=...` 这类覆盖直接报 `Key 'common' is not in struct`；② **原来是跑不起来的**：`AVHubertSeq2SeqConfig` 没有 `encoder_embed_dim` 字段，cross-attention 的 `kdim` 会回退成 `decoder_embed_dim`，只要它 ≠ 编码器的 768，第一次前向就 `RuntimeError: mat1 and mat2 shapes cannot be multiplied (204x768 and 1024x1024)`（已实测复现；受影响的是 README 让人先跑的 `smoke` / `train`） |
| `run_finetune.sh` | ① 词表路径自动探测（`$DATA/spm1000`、`$DATA/../spm1000`、`$DATA`）；② `common.user_dir` 指向 **`avhubert/` 包目录**（不是仓库根目录）；③ 新增 `fast` 模式与环境变量调参；④ 解码调用不再传 `task.*`（改 `override.data/label_dir`）；⑤ WER 文件按 `wer.*` 通配查找；⑥ 生成自包含配置后再训练；⑦ `BEAM` 可调 | 这七条都是**实测踩出来的硬阻塞**，逐条原因见 `训练加速与阻塞修复记录.md` §2 与 §2.1（例如第②条：fairseq `utils.py:479` 会 import `user_dir` 的最后一级目录名，必须是可导入的包 `avhubert`，否则报 `Could not infer task type`） |
| `pipeline_lrs2.sh` | ① `all` 模式改为**阶段内 N 个 rank 并行** + 逐个 pid 检查退出码；② 新增 `MODALITY=video`（默认）跳过抽音频；③ 第 5 步先清 stale `missing.list.*`、先检查缺失再合并、并对分片文件做存在性校验；④ 抽音频检查 ffmpeg 返回码、失败不留半截文件 | ① 原实现各 rank 串行，8 核只用 1 核（实测并行后 **6–6.6×**）；② 纯视觉不需要音频（见上）；③ 原顺序下 `cat` 会先于"存在缺失清单"的提示失败，而且残留清单会让本步**永远**失败；④ 转码失败原本要到几小时后才暴露 |

## 3. 环境侧的修复（不属于代码改动，但复跑必须知道）

| 问题 | 根因 | 解法 |
| --- | --- | --- |
| fairseq 无法导入 | 需 Python ≤3.10 | 用 3.8（3.12 报 dataclass 可变默认值错误） |
| dlib 装不上 | PyPI 无 cp38-linux wheel；conda classic solver 不收敛 | 下载 conda 包直接解压 + `apt install libatlas3-base` |
| dlib 缺 `GLIBCXX_3.4.29` | 系统 libstdc++ 过旧 | `patchelf --set-rpath <env>/lib` 写进 `.so`（**不要**用全局 `LD_LIBRARY_PATH`，否则 ffmpeg 崩） |
| `np.float` 不存在 | numpy 1.24 移除别名，而 skvideo 1.1.11 在用 | `sitecustomize.py` 垫片 |
| **训练完全起不来** | 环境里是 `hydra-core 1.3.7 + omegaconf 2.3.1`，而 `fairseq/setup.py` 要求 `hydra-core<1.1`、`omegaconf<2.1`（fairseq 自己 monkey-patch 了 `omegaconf._utils.is_primitive_type`，新版已删） | `pip install "hydra-core==1.0.7" "omegaconf==2.0.6"` |
| 大文件上传反复失败 | 手写 SFTP 分片续传有 bug | 改用平台 oss 工具（自带断点续传） |

## 4. 没有改动、但复现时要注意的官方行为

- **微调路线**：官方 checkpoint 是 LRS3(+VoxCeleb2) 预训练的，所以本项目走
  「加载官方权重 → 在 LRS2 main（train/val）上微调 → 在 LRS2 test 上测试」。
- **纯视觉配置**：`task.modalities: ["video"]`，微调时编码器的 w2v 部分在
  `freeze_finetune_updates` 步内被 `torch.no_grad()` 包住（`hubert_asr.py:493`）。
- **解码口径**：官方 `s2s_decode.yaml` 默认 `beam=50`；题目 §3.3.5 提到"CTC 贪心解码"，
  但仓库自带的 LRS2/LRS3 微调配置都是 **seq2seq**（解码器 + beam search），
  本项目跟随仓库配置，并在结果里写明 beam 大小。
- **`test.txt` 的两列**：第 2 列是 `NF`/`MV` 标记，来自 LRS2 pretrain 部分；
  官方流程不用它。本项目额外生成 `test_mv.{tsv,wrd}`，以便同时汇报「全量 1243 条」
  与「仅 MV 子集」两个口径。
